# Выбор модели для Google Colab с TPU v5e-1

Для Minecraft AI Bridge рекомендована **Gemma 4 E2B IT**: [`google/gemma-4-E2B-it`](https://huggingface.co/google/gemma-4-E2B-it). `IT` означает вариант, обученный следовать инструкциям. Он принимает текст и изображения, поддерживает несколько языков и вызов инструментов. Эти возможности подходят для выбора действий по наблюдениям моста и скриншотам Minecraft.

## Почему эта модель

У одного чипа [TPU v5e](https://docs.cloud.google.com/tpu/docs/v5e) **16 ГБ HBM**. В [таблице Google](https://ai.google.dev/gemma/docs/core#gemma-4-inference-memory-requirements) загрузка Gemma 4 E2B в BF16 оценивается примерно в **11,4 ГБ**, включая указанный в таблице запас на загрузку. Дополнительно нужна память для контекста и промежуточных вычислений. Поэтому начинать следует с коротких запросов и одного изображения.

Обозначение `E2B` относится к эффективному числу параметров при вычислениях. Полный набор весов значительно больше: около **5,1 млрд параметров**, включая таблицы эмбеддингов. Для памяти нужно учитывать полный размер.

| Вариант | Пригодность для одного v5e-1 |
| --- | --- |
| **Gemma 4 E2B IT, BF16** | Основной выбор: разумный запас памяти при коротком контексте; текст и изображения. |
| Gemma 3 4B IT, BF16 | Альтернатива с текстом, изображениями и реализацией в той же библиотеке Gemma для JAX. |
| Gemma 4 E4B IT, BF16 | Google оценивает загрузку в 17,9 ГБ: превышает память одного чипа. |

Это выбор по архитектуре, поддержке среды и требованиям к памяти. Скорость и качество управления Minecraft на реальном TPU в этом проекте пока не измерялись.

## Как запускать на TPU

**Ollama не поддерживает ускорение на TPU.** Выбор TPU в Colab и замена имени модели в существующем Ollama notebook не включат TPU-инференс. Перечень ускорителей Ollama приведён в [документации по оборудованию](https://docs.ollama.com/gpu).

Для прямой генерации внутри notebook можно использовать **JAX с поддержкой TPU и библиотеку [Gemma](https://github.com/google-deepmind/gemma)**. Библиотека поддерживает CPU, GPU и TPU, содержит архитектуру `gm.nn.Gemma4_E2B` и средства генерации ответов. Веса нужно загружать в совместимом с этой библиотекой формате; файл GGUF из Ollama для такого запуска не подходит.

Стартовые настройки [готового TPU notebook](../examples/vllm_tpu_colab.ipynb):

- BF16 для весов и основных вычислений; загрузка полного набора весов в FP32 превысит доступную память.
- Один запрос за раз: `batch_size = 1`.
- Общий бюджет контекста 3072 токена, включая ответ и изображение; ответ до 256 токенов. В notebook оставлен запас для инструкций, UUID сущностей и результата предыдущего действия; для простого текстового запроса можно уменьшить бюджет до 2048.
- Режим без дополнительных рассуждений, чтобы модель быстрее возвращала действие.
- Сначала текстовые наблюдения моста; затем один скриншот за запрос с небольшим бюджетом визуальных токенов.
- Первую генерацию оценивать отдельно: JAX компилирует вычисления, поэтому её задержка не показывает обычную скорость работы.

Даже при поддержке инструментов ответ модели должен проходить проверку допустимых действий и параметров в контроллере. Эта проверка уже есть в проекте.

## Замена Ollama с HTTP API: vLLM TPU

Если нужен сервер модели, похожий по роли на Ollama, рекомендован **[vLLM с TPU-плагином](https://docs.vllm.ai/projects/tpu/en/latest/)**. Официальный пакет установки называется `vllm-tpu`; он использует backend `tpu-inference`. В [быстром старте](https://docs.vllm.ai/projects/tpu/en/latest/getting_started/quickstart/) TPU **v5e** перечислен среди поддерживаемых поколений.

vLLM предоставляет [API, совместимый с OpenAI](https://docs.vllm.ai/en/latest/serving/online_serving/), включая `POST /v1/chat/completions`. Это формат запросов к локально запущенной модели; аккаунт или API-ключ OpenAI для такого инференса не нужны. Gemma 4 E2B IT есть в [таблице поддержки релизов TPU-плагина](https://docs.vllm.ai/projects/tpu/en/latest/recommended_models/).

Эта схема реализована в [vLLM TPU notebook](../examples/vllm_tpu_colab.ipynb) и [контроллере для Windows](../examples/vllm_colab.py). Пошаговый запуск — в [гайде](VLLM_TPU_COLAB_RU.md). Подключение устроено так:

1. В Colab запустить vLLM TPU и модель, привязав API к `127.0.0.1`, например на порту 8000.
2. Ячейка notebook получает задание с Windows через существующий relay.
3. Вместо `POST /api/chat` в Ollama ячейка вызывает `POST http://127.0.0.1:8000/v1/chat/completions`. Нужно преобразовать параметры запроса и изображения в формат OpenAI API, а текст ответа взять из `choices[0].message.content`.
4. Из ответа разобрать JSON с `action`, `parameters`, `reason` и вернуть его на `/result` Windows relay с тем же `job_id`. Python-контроллер проверит решение и отправит задачу моду через WebSocket.

Туннель ngrok при этой схеме работает на Windows; ячейка Colab обращается к серверу модели локально. Для vLLM не нужно публиковать отдельный внешний адрес в Colab.

Выбирать следует релизную версию плагина. На момент проверки таблица для nightly/main отмечает ошибки проверки корректности Gemma 4 E2B, тогда как таблица релизов отмечает успешные проверки. Поддержка генерации по строгой JSON-схеме (`structured_decoding`) отмечена как непроверенная; существующую настройку Ollama `format` нельзя просто перенести в vLLM без проверки. Проверка JSON и доступных действий в контроллере обязательна.

Документация установки ориентирована на **Google Cloud TPU VM**. Поддержка поколения v5e и модели сама по себе не подтверждает, что вся комбинация библиотек работает в конкретной сессии **Colab с v5e-1**. Такой запуск, память сервера и задержку ответов в проекте ещё нужно проверить на реальном TPU.

## Что меняется в подключении мода

Схема для TPU:

```text
Colab: Gemma + JAX на TPU
    ↕ HTTPS: наблюдение и JSON-решение
Windows: ngrok → Python-контроллер → Minecraft AI Bridge
```

Мод и протокол локального контроллера подходят для этой схемы. В Colab нужно заменить обращение к локальному API Ollama на вызов vLLM TPU или генерацию через Gemma/JAX и преобразовать ответ в существующий JSON-формат решения.

**[Ollama notebook](../examples/ollama_colab.ipynb) использует GPU. Для TPU используй [vLLM TPU notebook](../examples/vllm_tpu_colab.ipynb) и [его гайд](VLLM_TPU_COLAB_RU.md).** Этот документ фиксирует выбор модели и требования к памяти.
