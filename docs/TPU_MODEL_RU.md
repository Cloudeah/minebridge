# Выбор модели для Google Colab с TPU v5e-1

Для Minecraft AI Bridge рекомендована **Gemma 4 E2B IT**: [`google/gemma-4-E2B-it`](https://huggingface.co/google/gemma-4-E2B-it). `IT` означает вариант, обученный следовать инструкциям. Он принимает текст и изображения, поддерживает несколько языков и вызов инструментов. Эти возможности подходят для выбора действий по наблюдениям моста и скриншотам Minecraft.

## Почему эта модель

У одного чипа [TPU v5e](https://docs.cloud.google.com/tpu/docs/v5e) **16 ГБ HBM**. В [таблице Google](https://ai.google.dev/gemma/docs/core#gemma-4-inference-memory-requirements) загрузка Gemma 4 E2B в BF16 оценивается примерно в **11,4 ГБ**, включая указанный в таблице запас на загрузку. Дополнительно нужна память для контекста и промежуточных вычислений. Поэтому начинать следует с коротких запросов и одного изображения.

Обозначение `E2B` относится к эффективному числу параметров при вычислениях. Полный набор весов значительно больше: около **5,1 млрд параметров**, включая таблицы эмбеддингов. Для памяти нужно учитывать полный размер.

| Вариант | Пригодность для одного v5e-1 |
| --- | --- |
| **Gemma 4 E2B IT, BF16** | Основной выбор: разумный запас памяти при коротком контексте; текст и изображения. |
| Gemma 3 4B IT, BF16 | Альтернатива с текстом, изображениями и реализацией в той же библиотеке Gemma для JAX. |
| Gemma 4 E4B IT, BF16 | Google оценивает загрузку в 17,9 ГБ: превышает память одного чипа. |

Это выбор по архитектуре, поддержке среды и требованиям к памяти. Скорость и качество управления Minecraft на реальном TPU в этом проекте пока не измерялись.

## Как запускать на TPU

**Ollama не поддерживает ускорение на TPU.** Выбор TPU в Colab и замена имени модели в существующем Ollama notebook не включат TPU-инференс. Перечень ускорителей Ollama приведён в [документации по оборудованию](https://docs.ollama.com/gpu).

Для выбранной модели нужен **JAX с поддержкой TPU и библиотека [Gemma](https://github.com/google-deepmind/gemma)**. Библиотека поддерживает CPU, GPU и TPU, содержит архитектуру `gm.nn.Gemma4_E2B` и средства генерации ответов. Веса нужно загружать в совместимом с этой библиотекой формате; файл GGUF из Ollama для такого запуска не подходит.

Стартовые настройки для последующей реализации TPU notebook:

- BF16 для весов и основных вычислений; загрузка полного набора весов в FP32 превысит доступную память.
- Один запрос за раз: `batch_size = 1`.
- Общий бюджет контекста около 2048 токенов, включая ответ и изображение; ответ до 256 токенов.
- Режим без дополнительных рассуждений, чтобы модель быстрее возвращала действие.
- Сначала текстовые наблюдения моста; затем один скриншот за запрос с небольшим бюджетом визуальных токенов.
- Первую генерацию оценивать отдельно: JAX компилирует вычисления, поэтому её задержка не показывает обычную скорость работы.

Даже при поддержке инструментов ответ модели должен проходить проверку допустимых действий и параметров в контроллере. Эта проверка уже есть в проекте.

## Что меняется в подключении мода

Схема для TPU:

```text
Colab: Gemma + JAX на TPU
    ↕ HTTPS: наблюдение и JSON-решение
Windows: ngrok → Python-контроллер → Minecraft AI Bridge
```

Мод и протокол локального контроллера подходят для этой схемы. В Colab нужно заменить обращение к локальному API Ollama на генерацию через Gemma/JAX и преобразование ответа в существующий JSON-формат решения.

**Готовый [Ollama notebook](../examples/ollama_colab.ipynb) использует GPU и не является реализацией этого TPU-варианта.** Этот документ фиксирует выбор модели и требования к отдельному TPU notebook.
