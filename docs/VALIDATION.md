# Проверки реализации 0.3.0

Проверено в облачной среде **Linux x86_64, JDK 25, Minecraft 26.1.2, NeoForge 26.1.2.97**. Игровые сценарии выполнялись через Python SDK в настоящем клиенте Minecraft через NeoForge dev-loader, в одиночном мире `BridgeSmoke`, под Xvfb с Mesa llvmpipe. Это проверка поведения, а не измерение производительности компьютера пользователя.

## Автоматические проверки

```bash
python scripts/dev.py :core:test :mod:build
.venv/bin/python -m unittest discover -s python -p 'test_*.py'
```

Сборка успешна: **80 Java-тестов**, без ошибок и пропусков. Python-набор: **50 тестов**, все прошли за **27,764 секунды**.

Проверки охватывают авторизацию и права владельца, фильтрацию capabilities, состояние задач/целей, отмену и запоздалые решения, дедупликацию, сроки/бюджеты, компактные наблюдения, память, планировщики и формат MBV1. Новые проверки охватывают относительные координаты/углы, серверный подсчёт прыжков и длительности приседания, отпускание управления, неверные типы/диапазоны параметров и конфликт бега с приседанием.

Python-интеграция использует настоящий локальный HTTP/WebSocket и код функций опубликованного notebook с фиксированными ответами тестового API. Проверены передача решений/PNG, токены relay, Colab Secrets с ручным резервным вводом, лимиты контекста/времени/действий, повтор генерации неверного JSON, повтор доставки того же результата и отказ истёкшему заданию. Тестовый API не запускает нейросеть.

Официальные tokenizer и chat template Gemma 4 E2B проверены на CPU с 19 доступными действиями, шестью блоками, четырьмя сущностями, двумя предметами и предыдущим результатом. После сжатия инструкций и служебных полей результата запрос содержит до 2450 входных токенов; повтор с уточнением — 2530. Вместе с резервом 256 токенов ответа это 2786 из 3072. Это измерение конкретных наблюдений; перед каждой генерацией notebook дополнительно проверяет фактическую длину через `/tokenize`.

## Новые сценарии в Minecraft

| Сценарий | Фактический результат |
| --- | --- |
| Относительный поворот | `look.turn` с yaw +90° и pitch +30°, затем обратный поворот, завершились с серверным подтверждением; каждой задаче хватило `max_actions: 1` |
| Приседание на месте | `move.crouch` с `ticks: 40` и `max_actions: 1` подтвердил 41 тик и отпускание перед успехом |
| Десять прыжков | `move.jump` с `count: 10`, `max_actions: 10`: ровно десять подтверждённых отрывов/приземлений |
| Относительное движение вперёд | `forward: 2`, `tolerance: 0.35`: сервер подтвердил конечную позицию, остаток расстояния 0,31575 блока |
| Движение вправо пригнувшись | `right: 2`, `crouch: true`: сервер подтвердил конечную позицию, остаток расстояния 0,27522 блока |
| F7 во время приседания | Для задачи на 80 тиков открытие окна отпустило управление и заморозило продвижение; одна секунда в окне не засчиталась в приседание. После закрытия задача завершилась с 81 подтверждённым тиком |
| F9 внутри F7 | Задача отменена с частичным результатом 12 тиков приседания. Закрытие окна не возобновило приседание |
| Переключаемые клавиши | При `toggleCrouch: true` подтверждены 60 тиков и отпускание; F9 в F7 не восстановил приседание после закрытия окна. Настройки владельца сохранены |
| Бег и точная конечная точка | При `toggleSprint: true` движение на восемь блоков с допуском 0,35 завершилось с серверным остатком 0,04726 блока. Исправлено движение к центру последнего блока вместо заданной точки |
| Окно во время бега | F7 отпустил движение и остановил расход действий; F9 отменил задачу после четырёх нажатий. Закрытие F7 не восстановило бег |
| Неверные параметры | Неверные типы, диапазоны и конфликтующие флаги отклонены до исполнения. `move.to` с одним `entity_id` без `target` также отклонён |

Результаты перемещения, относительного поворота и приседания содержат `source: integrated_server`. Значения сверх запрошенной длительности приседания отражают задержку серверного наблюдения; задача ждёт подтверждённого отпускания.

## Границы проверок

В этой среде **нет TPU**. Реальный инференс Gemma/vLLM TPU, компиляция и память на v5e-1, Windows, публичный ngrok и установка JAR в отдельный пользовательский launcher здесь не проверялись. Пользователь сообщил об успешном запуске модели и передаче команд; это не локальный замер качества, скорости или памяти.

Не проверялись все vanilla-рецепты, все ориентации/многоблочные блоки, сторонние сборки и шейдеры, выделенный сервер и стресс-нагрузка медленного получателя. Ограничения механик перечислены в [README](../README.md), параметры — в [API](API.md). Порядок запуска и диагностика — в [едином Windows/vLLM TPU гайде](INGAME_VLLM_RU.md).
