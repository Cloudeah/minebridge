# Проверки реализации 0.6.0

Проверено в облачной среде **Linux x86_64, JDK 25, Minecraft 26.1.2, NeoForge 26.1.2.97**. Игровые сценарии выполнялись через Python SDK в настоящем клиенте Minecraft через NeoForge dev-loader, в одиночном мире `BridgeSmoke`, под Xvfb с Mesa llvmpipe. Это проверка поведения, а не измерение производительности компьютера пользователя.

## Автоматические проверки

```bash
python scripts/dev.py :core:test :mod:build
.venv/bin/python -m unittest discover -s python -p 'test_*.py'
```

Сборка успешна: **122 Java-тестов**, без ошибок и пропусков. Python-набор: **58 тестов**, все прошли.

Проверки охватывают авторизацию и права владельца, фильтрацию capabilities, состояние задач/целей, отмену и запоздалые решения, дедупликацию, сроки/бюджеты, компактные наблюдения, память, планировщики и формат MBV1. В 0.6.0 добавлены проверки происхождения серверного урона, конкретного UUID стрелы, временных окон отдельного удара, изоляции актёров/целей/измерений, запрета повторного выпуска, ручных ударов на паузе и атомарного сохранения терминального результата. Защищённые queries, память ресурсов и предварительные бюджеты кликов из 0.5.0 остаются в наборе.

Python-интеграция использует настоящий локальный HTTP/WebSocket и код функций опубликованного notebook с фиксированными ответами тестового API. Проверены передача решений/PNG, токены relay, Colab Secrets с ручным резервным вводом, лимиты контекста/времени/действий, повтор генерации неверного JSON, повтор доставки того же результата и отказ истёкшему заданию. Новые сценарии проверяют запрос плана перед действием, две последовательные цели владельца и сокращение слишком большого наблюдения через `/tokenize` с сохранением цели и подтверждённого прогресса. Дополнительно проверен путь решения `combat.ranged` через notebook, HTTP-relay и защищённую WebSocket-задачу с неизменными параметрами, целями и лимитами. Тестовый API не запускает нейросеть.

Официальные tokenizer и chat template Gemma 4 E2B проверены на CPU на **148 вариантах запросов**, включая повтор генерации, результаты игровых проверок боя и отмены, план крафта и полный инвентарь из 36 слотов. Объявлены 23 игровых действия и `query` с семью операциями; наблюдения содержат шесть блоков, четыре предметные сущности и роли слотов. Исходный максимум — **3315 входных токенов**. После автоматического сокращения наблюдений максимум вместе с резервом 256 токенов ответа — **3070 из 3072**, потребовалось не более четырёх сокращений. Это измерение конкретных запросов; перед каждой генерацией notebook проверяет фактическую длину через `/tokenize` и прекращает запрос, если обязательные данные не помещаются.

## Новые сценарии боя в Minecraft 0.6.0

| Сценарий | Фактический результат |
| --- | --- |
| Одиночный выстрел | Обычный лук в основной руке выпустил одну стрелу и попал в тестовую свинью на расстоянии шести и восьми блоков. Два действия, один UUID стрелы владельца, одно подтверждённое попадание и положительный урон; израсходована ровно одна стрела |
| Предварительные отказы | При бюджете один, слишком малом `max_distance`, отсутствии стрел или выбранного лука натяжение не начиналось; расход действий нулевой |
| Нет подтверждённого урона | Стрела попала в неуязвимую тестовую цель. Задача вернула `hit_unconfirmed`, сохранила `shots: 1`, `hits: 0` и не выпустила вторую стрелу |
| Отмена во время натяжения | `task.cancel` и F9 сохранили восемь стрел, неповреждённый лук и выбранный hotbar; `actions: 1`, выстрела нет |
| F7 при натяжении | Окно прервало натяжение без выстрела. После закрытия задача завершилась `draw_interrupted`, сохранив стрелы |
| Разрыв связи при натяжении | Задача осталась на паузе без выстрела. Переподключение не возобновило её; явное `task.resume` вернуло `draw_interrupted` |
| Последний ближний удар | При бюджете один задача сохранила ровно один подтверждённый hit и урон, затем закончилась `action_limit`; ложного поражения нет |
| Поражение цели | Один удар мечом по тестовой цели с одним здоровьем завершился `succeeded` при `max_actions: 1`; поражение подтверждено серверным событием урона от нашего игрока |
| Ручной удар на паузе | После одного командного удара задача приостановлена. Обычный ручной удар снизил здоровье тестовой свиньи с девяти до восьми; отменённая задача сохранила только один hit и один урон, не приписав себе ручной удар |
| Цель владельца в F7 | Защищённая `combat.ranged` задача выполнила цель из игры; повторно открытое окно показало один выстрел, одно попадание и фактический положительный урон |

Выстрел выполняется штатными использованием и отпусканием лука. Отмена натяжения использует обычные пакеты переключения hotbar туда и обратно: обычный `RELEASE_USE_ITEM` выпустил бы стрелу. Факт выпуска принимается только для новой серверной стрелы и её первого игрового тика; загрузка старой стрелы из сохранения не считается новым выстрелом. Попадание учитывается по `LivingDamageEvent.Post` от конкретного снаряда владельца. Временные окна receipts используют серверный тик из подтверждающего снимка, поскольку клиентский счётчик может опережать сервер. Отмена после выпуска не удаляет стрелу; терминальный результат фиксирует только receipts, полученные к его атомарной фиксации.

Частичная вставка Minecraft может изменить инвентарь, но пропустить итоговое событие подбора. Этот случай подтверждается совпадающими изменениями предметного стака и инвентаря после серверного события столкновения в том же тике. Проверка ничего не выдаёт и не удаляет. Исчезновение сущности само по себе не подтверждает подбор.

## Границы проверок

В этой среде **нет TPU**. Реальный инференс Gemma/vLLM TPU, компиляция и память на v5e-1, Windows, публичный ngrok и установка JAR в отдельный пользовательский launcher здесь не проверялись. Пользователь сообщил об успешном запуске модели и передаче команд; это не локальный замер качества, скорости или памяти.

Не проверялись все vanilla-рецепты, все ориентации/многоблочные блоки, сторонние сборки и шейдеры, выделенный сервер и стресс-нагрузка медленного получателя. Ограничения механик перечислены в [README](../README.md), параметры — в [API](API.md). Порядок запуска и диагностика — в [едином Windows/vLLM TPU гайде](INGAME_VLLM_RU.md).
