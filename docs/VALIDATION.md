# Проверки реализации 0.4.0

Проверено в облачной среде **Linux x86_64, JDK 25, Minecraft 26.1.2, NeoForge 26.1.2.97**. Игровые сценарии выполнялись через Python SDK в настоящем клиенте Minecraft через NeoForge dev-loader, в одиночном мире `BridgeSmoke`, под Xvfb с Mesa llvmpipe. Это проверка поведения, а не измерение производительности компьютера пользователя.

## Автоматические проверки

```bash
python scripts/dev.py :core:test :mod:build
.venv/bin/python -m unittest discover -s python -p 'test_*.py'
```

Сборка успешна: **98 Java-тестов**, без ошибок и пропусков. Python-набор: **52 теста**, все прошли.

Проверки охватывают авторизацию и права владельца, фильтрацию capabilities, состояние задач/целей, отмену и запоздалые решения, дедупликацию, сроки/бюджеты, компактные наблюдения, память, планировщики и формат MBV1. В 0.4.0 добавлены проверки последовательного выброса, устаревших/повторных наблюдений, возобновления подтверждения после паузы, точного бюджета без новой мутации, принадлежности факта подбора игроку/измерению/сущности, частичной вставки и различия использования предмета и наблюдаемого изменения.

Python-интеграция использует настоящий локальный HTTP/WebSocket и код функций опубликованного notebook с фиксированными ответами тестового API. Проверены передача решений/PNG, токены relay, Colab Secrets с ручным резервным вводом, лимиты контекста/времени/действий, повтор генерации неверного JSON, повтор доставки того же результата и отказ истёкшему заданию. Тестовый API не запускает нейросеть.

Официальные tokenizer и chat template Gemma 4 E2B проверены на CPU с 21 доступным действием модели, шестью блоками, четырьмя предметными сущностями, двумя предметами инвентаря, обеими руками и предыдущими результатами игровых проверок. В этом наборе запрос содержит до 2642 входных токенов; повтор с уточнением — 2722. Вместе с резервом 256 токенов ответа это 2978 из 3072. Это измерение конкретных наблюдений; перед каждой генерацией notebook дополнительно проверяет фактическую длину через `/tokenize`.

## Новые сценарии в Minecraft

Итерация закрывает подбор/выбрасывание предметов и дорабатывает проверку использования из раздела 6 исходного документа `Minecraft_AI_Bridge.docx`.

| Сценарий | Фактический результат |
| --- | --- |
| Точный выброс | Из 10 камней выброшены ровно 5; `actions: 5`, `confirmed_changes.drop.count: 5`, в основной руке осталось 5. Точного бюджета хватило на последнее подтверждение |
| Обычный подбор | Игрок подошёл к наблюдаемому стаку из 5 камней; сервер подтвердил подбор этого UUID этим игроком, в руке снова 10 |
| Неиспользуемый предмет / пустая рука | Камень дал `use_no_effect`, пустая рука — `empty_hand`; ложного успеха нет |
| Короткое и полное использование еды | При коротком удержании подтверждено использование без съеденного яблока. Полное удержание съело ровно одно яблоко, повысило сытость и не запустило повтор; каждой задаче хватило `max_actions: 1` |
| Вторая рука и наведение | Использование снежка из offhand с `target` уменьшило стак на один предмет и увеличило серверный счётчик использования |
| Частичный подбор | При 63 камнях в одном слоте и остальных заполненных слотах из стака 3 подобран 1; ошибка `inventory_full`, `remaining: 2`, подтверждённое количество сохранено |
| Полностью заполненный инвентарь | Неподходящий стак не подобран; ожидание закончилось `pickup_unconfirmed` до общего срока задачи, подтверждение подбора не выдумано |
| Остановка выброса | Остановка серии на 64 предмета сохранила частичный результат; количество в руке после обработки уже отправленного действия осталось стабильным |
| F7 при выбросе | Пауза дольше 20 тиков не вызвала повтор отправленного выброса; после закрытия окна серия закончилась ровно десятью действиями |
| F9 во время еды | Удержание использования отпущено, задача отменена, золотое яблоко не съедено; повтор и автоматическое возобновление отсутствуют |
| Неподдерживаемые параметры | Выброс offhand и `count` для подбора всего стака отклонены до исполнения |

Частичная вставка Minecraft может изменить инвентарь, но пропустить итоговое событие подбора. Этот случай подтверждается совпадающими изменениями предметного стака и инвентаря после серверного события столкновения в том же тике. Проверка ничего не выдаёт и не удаляет. Исчезновение сущности само по себе не подтверждает подбор.

| Движение вправо пригнувшись | `right: 2`, `crouch: true`: сервер подтвердил конечную позицию, остаток расстояния 0,27522 блока |
| F7 во время приседания | Для задачи на 80 тиков открытие окна отпустило управление и заморозило продвижение; одна секунда в окне не засчиталась в приседание. После закрытия задача завершилась с 81 подтверждённым тиком |

| Переключаемые клавиши | При `toggleCrouch: true` подтверждены 60 тиков и отпускание; F9 в F7 не восстановил приседание после закрытия окна. Настройки владельца сохранены |
| Бег и точная конечная точка | При `toggleSprint: true` движение на восемь блоков с допуском 0,35 завершилось с серверным остатком 0,04726 блока. Исправлено движение к центру последнего блока вместо заданной точки |
| Окно во время бега | F7 отпустил движение и остановил расход действий; F9 отменил задачу после четырёх нажатий. Закрытие F7 не восстановило бег |
| Неверные параметры | Неверные типы, диапазоны и конфликтующие флаги отклонены до исполнения. `move.to` с одним `entity_id` без `target` также отклонён |

Результаты перемещения, относительного поворота и приседания содержат `source: integrated_server`. Значения сверх запрошенной длительности приседания отражают задержку серверного наблюдения; задача ждёт подтверждённого отпускания.

## Границы проверок

В этой среде **нет TPU**. Реальный инференс Gemma/vLLM TPU, компиляция и память на v5e-1, Windows, публичный ngrok и установка JAR в отдельный пользовательский launcher здесь не проверялись. Пользователь сообщил об успешном запуске модели и передаче команд; это не локальный замер качества, скорости или памяти.

Не проверялись все vanilla-рецепты, все ориентации/многоблочные блоки, сторонние сборки и шейдеры, выделенный сервер и стресс-нагрузка медленного получателя. Ограничения механик перечислены в [README](../README.md), параметры — в [API](API.md). Порядок запуска и диагностика — в [едином Windows/vLLM TPU гайде](INGAME_VLLM_RU.md).
